What is GenAI?

Generative AI (GenAI) tools, such as Microsoft Copilot, can help you identify and fix common R and RStudio errors. They can be useful for understanding error messages and learning how to write or debug code.

How to write a useful GenAI prompt

  • Ask a clear question. For example: “What does this R error mean, and how can I fix it?”
  • Ask for an explanation. For example: “Explain what you have changed and why.”
  • Provide relevant context. Include the line of code that caused the error and the exact error message shown in R. You can also include earlier code if it helps explain the problem, provided it is appropriate to share.

Example of a useful prompt

“I ran the following code in R:

mydata <- read.csv("data.numbers")

I got this error message:

Error in file(file, "rt") : cannot open the connection
In addition: Warning message:
In file(file, "rt") : cannot open file 'data.numbers': No such file or directory

I am using a MacBook, and I think the file might have been downloaded as a Numbers file. Can you explain what caused this error, what changes you recommend, and why those changes will fix the problem?”

When using GenAI, remember

  • Follow the University’s rules and guidance on using GenAI.
  • Read and understand any suggested solution before implementing it.
  • GenAI can guide you, but you are responsible for checking that the code works.

Note: Do not upload the following to GenAI tools:

  • Personal data — do not share personal or sensitive information.
  • Assessment content — do not upload University-owned assessment materials.
  • Data downloaded from the GBD database — sharing these data may breach copyright or licensing conditions and could put the University’s access at risk.

If you have questions about troubleshooting with GenAI, please ask teaching staff during a lab session.

2.1 OneDrive storage for everything apart from RStudio

The University provides you with 500 GB of secure OneDrive storage. Files saved to OneDrive are stored in the cloud rather than only on one computer, and changes can be synchronised across your devices.

You can use OneDrive to store and organise your University files, including assessment briefs, coursework you are working on, lecture materials, readings, and other study documents.

You can access your OneDrive files in several ways:

  • On any University computer: Sign in to a University computer using your University of Bath account. From the taskbar, navigate to File Explorer (the yellow folder icon) → OneDrive (the blue cloud icon). Alternatively, search for "onedrive" in the Windows Start menu.
  • On any web browser: Sign in to Microsoft 365 using your University of Bath account and navigate to Apps and more → OneDrive. Alternatively, you can sign in directly to OneDrive.
  • On any mobile device: Download the OneDrive app and sign in using your University of Bath account.

2.2 H: drive storage for RStudio

The University also provides you with an H: drive, a secure, backed-up storage space on the University network.

Throughout this unit, you will use a software application called RStudio to work with data. Because cloud synchronisation can sometimes cause issues when working with RStudio files and datasets, we will use your H: drive rather than OneDrive to store this work.

2.3 Accessing your H: drive on a University PC

3.1 Before You Install R and RStudio

R is a programming language used to analyse data, perform calculations, and create graphs. RStudio is an integrated development environment (IDE), an application that makes it easier to write, run, and organise R code.

Throughout this textbook, you will use a University PC or UniDesk on your personal device. Both R and RStudio should already be installed and up to date on these systems.

To confirm that RStudio is available on a University PC or through UniDesk, follow the steps below:

Log on to a University PC or UniDesk

Log on to a University PC or access UniDesk on your personal device (covered in Section 2.4).

Search for RStudio

Open the Windows Start menu and search for “rstudio”.

Open RStudio

If RStudio appears, open it and confirm that it launches successfully.

Note: If an Update Available! pop-up appears, always select Ignore Update. Updates to University-managed software are handled by University IT Services.

If RStudio opens successfully, no further installation or updates are required. Read through Section 3.2 without downloading anything, then continue to Section 3.3.

If RStudio does not appear or fails to open, contact University IT Services for assistance (see Section 2.5), as you are unlikely to have permission to install or configure it yourself.

3.2 Installing or Updating R and RStudio

If you would like to install or update R and RStudio on your personal computer, follow the two steps below in order:

Install or Update Base R

Start by visiting CRAN and selecting the download link for your operating system: Windows, macOS, or Linux.

  • Windows: Select Download R for Windows → base → the download link at the top of the page.
  • macOS: Select Download R for macOS → the latest compatible version (select arm64 for most modern Macs).
  • Linux: Select Download R for Linux → your Linux distribution, then follow the installation or update instructions.

Run the installer and follow the instructions. In most cases, you should use the default installation location.

Install or Update RStudio

Once R is installed or updated, visit the RStudio Desktop download page and choose the installer for your operating system.

  • Windows: Select Download RStudio → the Windows installer (.exe), then follow the instructions.
  • macOS: Select Download RStudio → the macOS installer (.dmg), then follow the instructions.
  • Linux: Select Download RStudio → the installer for your Linux distribution, then follow the installation or update instructions.

Run the installer and follow the instructions. In most cases, you should use the default installation location.

3.3 RStudio Settings

Before you begin using RStudio, we recommend making a few adjustments to make it easier to access and use.

  • Pin RStudio for easy access: To make RStudio easier to access in the future, you can pin it to the taskbar (Windows) or Dock (Mac) at the bottom of your screen. To do this, open RStudio, right-click its icon in the taskbar or Dock, and select Pin to taskbar (Windows) or Options → Keep in Dock (Mac).
  • Start with a clear workspace: In RStudio, go to Tools → Global Options → General and untick Restore .RData into workspace at startup. This prevents objects from previous sessions being automatically loaded when you open RStudio.
  • Do not automatically save the workspace: Under General, set Save workspace to .RData on exit to Never. This encourages you to save your code in scripts rather than relying on previously saved objects.
  • Choose an accessible appearance: Under Appearance, you can customise RStudio by choosing a light or dark theme and adjusting the font size to suit your preferences.

Unless you have a specific reason to change them, we recommend leaving all other settings at their defaults.

4.1 The RStudio Interface

In the previous chapter, you learnt how to access R and RStudio. You learnt that R is a programming language that allows you to write and run code, and RStudio is a program that makes working with R easier.

Open RStudio on your computer. When RStudio opens, you will see four different areas on the screen. These are called panes.

  • Upper left – Source: Where you write, edit, and save your code. This area may not appear until you open a file.
  • Lower left – Console: Where you type and run code directly and see the results. Code entered here is not automatically saved.
  • Upper right – Environment and Help:
    • Environment: Shows objects (such as data) you have created and stored in R.
    • Help: Provides information and guidance on using R functions and packages.
  • Lower right – Files, Plots, Packages, and Viewer:
    • Files: Browse files and folders on your computer.
    • Plots: View graphs you create in R.
    • Packages: View, install, and manage R packages.
    • Viewer: Display certain types of output, such as interactive graphs and web content.

4.2 Running Your First R Code

Let's start by running your first line of R code in RStudio.

Find the Console

Find the Console in RStudio (the bottom-left pane).

Copy the code

Click the copy button on the right-hand side of the code box below.

Paste the code

In the Console, paste the code next to the >.

Run the code

Press Enter to run it.

Run in the console
1 + 1

R should return [1] 2. R calculated 1 + 1 and returned 2. The [1] indicates where the output begins.

You've just run your first line of R code!

Note: Throughout this textbook, you can use the copy button on code boxes to copy code into the Console. You can also type the code directly.

Your turn

  • + Addition (e.g., 5 + 3)
  • - Subtraction (e.g., 10 - 4)

  • / Division (e.g., 12 / 3)
  • ^ Powers (e.g., 2 ^ 3)

Try combining calculations using brackets, such as (2 + 3) * 4. Press Enter after each calculation to see the result.

4.3 Accessing Additional Tools

As you have already seen, R comes with some built-in functionality, but some tasks require additional tools. For example, you might want to create more advanced graphs, analyse particular types of data, or use specialised statistical methods.

These additional tools are called packages. Packages extend what R can do by providing new functions.

Most packages are downloaded from CRAN, the Comprehensive R Archive Network. To use a package, you must first install it on your computer and then load it into your R session.

4.4 Installing and Loading Packages

Installing a package

Packages are installed using install.packages(). Think of this like installing an app on your phone: you only need to install a package once for each R installation.

Let's start by installing a simple package called beepr, which allows R to play sounds.

Run in the console
install.packages("beepr")

After pressing Enter, R will attempt to download and install the package. An installation is successful when R finishes the command without an error.

When you install a package, you may see messages in the Console containing phrases such as trying URL, downloaded, or * DONE. These describe the installation process and are normal. You may also see a WARNING, which does not necessarily indicate a problem and in most cases should be ignored.

Note: If you see a message beginning with Error, the package may not have installed successfully, and you may need to troubleshoot the problem.

Loading a package

Packages are loaded using the library() function. Think of this like using an app on your phone: even after you have installed an app, you will need to open it each time you want to use it.

After installing the beepr package, load it into your current R session:

Run in the console
library(beepr)

When you load a package, you may see no message at all, or you may see informational messages beginning with words such as Loading, Attaching, or The following objects are masked. These are normal and do not necessarily indicate a problem.

Note: If you see a message beginning with Error, the package may not have loaded successfully, and you may need to troubleshoot the problem.

4.5 Functions and Arguments

A function is a set of instructions that tells R to perform a particular task. For example, you have already used two functions: install.packages() to install a package and library() to load a package.

Every function has a name followed by parentheses (). Inside these parentheses, you can provide arguments, which give the function additional information about what you want it to do.

For example, in library(beepr), library() is the function and beepr is the argument, telling R which package to load.

Within the beepr package, there is a function called beep() that tells R to play a sound.

Turn up the volume on your device! Let's start by running beep() without any arguments.

Run in the console
beep()

Some arguments are required, while others have default values and only need to be specified if you want to change them. By default, beep() plays sound number 1. You can change the sound by adding the sound argument inside the parentheses.

Run in the console
beep(sound = 8)

This tells R to run the beep() function and play sound number 8.

Your turn

Try changing the sound argument to different whole numbers between 1 and 11.

Which sounds do you hear?

The arguments for a function are not always clear. You can find information about a function and its arguments using ? followed by the function name. Try this with the beep() function.

Run in the console
?beep

The documentation will appear in the Help pane (bottom-right pane) in RStudio.

4.6 Objects

An object is a named place where R stores information, such as a number, text, or dataset, so that you can use it again later. You create an object using the assignment operator <-, which tells R to store a value under a particular name.

For this example, we will use the University of Bath and an example ranking of 5 to practise creating objects:

Run in the console
name <- "University of Bath"rank <- 5

Here, "University of Bath" is stored in an object called name, and the example ranking 5 is stored in an object called rank. You should see both objects appear in the Environment pane (top-right pane).

To see what an object contains, type its name into the Console and press Enter:

Run in the console
namerank

Objects can also be used in functions and calculations. For example, we can convert the university name to uppercase and subtract two from the example ranking:

Run in the console
toupper(name)rank - 2

Objects can store other types of information too. For example, we can store today’s date and the date the University of Bath was officially founded:

Run in the console
today <- Sys.Date()founded <- as.Date("1966-10-25")

today stores the current date returned by R, while founded stores 25 October 1966, when the University of Bath was established by Royal Charter.

We can then calculate how many days have passed since the University was founded:

Run in the console
bath_days_old <- today - foundedbath_days_old

Here, R subtracts the founding date from today’s date and stores the result in a new object called bath_days_old.

Your turn

  1. Now try the same calculation for yourself. Run the following line of code, replacing the example date with your own date of birth (in YYYY-MM-DD format).
Run in the console
birthday <- as.Date("2001-12-25")
  1. Now run these two lines of code to calculate and display how many days old you are. We use your_days_old so your result is stored separately from bath_days_old.
Run in the console
your_days_old <- today - birthdayyour_days_old

You will create and work with many different objects throughout this course. For now, the important thing to remember is that an object allows you to give something a name, store it, and use it again later.

4.7 Getting the Code Right

You may have already noticed that R requires you to write code precisely. Small differences in spelling, capitalisation, quotation marks, symbols, or brackets can change what your code does or cause an error.

Note: Typing mistakes are a common cause of errors when coding. If your code does not work as expected, check your spelling, capitalisation, symbols, quotation marks, and brackets.

4.10 Glossary

This glossary defines common terms you have encountered in this chapter. Learning this vocabulary can help you understand R instructions and search for solutions when you need help.

TermDefinition
argumentAn input or option you give to a function to control what it does.
CRANThe Comprehensive R Archive Network, where you can download R and many R packages.
default valueThe value a function uses for an argument when you do not specify one.
functionA named set of instructions that performs a task and can be used again.

5.0 Learning Outcomes

By the end of this lesson, you should be able to:

  • Understand the importance of organising your R scripts, datasets, and other files;
  • Create and open an RStudio Project;
  • Understand what a working directory is and why it matters;
  • Create, annotate, save, and run an R script.

5.1 Why organise your workspace?

Throughout the remaining lessons, you will create and work with different types of files. Keeping these organised will help you find your work, avoid mistakes, and return to your analyses later.

Some of the file types you will encounter include:

  • RStudio Project files (.Rproj): Files that allow you to open an RStudio Project and its associated workspace.
  • R scripts (.R): Files containing the R code you have written.
  • Data files (.csv, .xlsx): Files containing datasets you want to analyse.
  • Output files (.jpg, .png, .txt): Files containing graphs, text results, or other outputs from your analyses.

5.2 Naming conventions

Before creating files, it is useful to follow a few simple naming rules. We recommend:

  • Using only letters, numbers, hyphens (-), and underscores (_) in filenames, apart from the full stop before the file extension. Avoid spaces and other special characters.
  • Using lowercase letters consistently.
  • Choosing descriptive names that clearly identify the contents of a file.
  • Using hyphens (-) to separate words and underscores (_) to separate different parts of a filename, such as a lesson number and description.

For example, lesson-3_health-data.csv is a clear, descriptive filename.

These are recommended conventions rather than strict R requirements. Following them will make your files easier to find and use in RStudio.

5.3 Creating an RStudio Project

An RStudio Project is a convenient way to organise your R scripts, datasets, and other files in one place. For this workbook, we will create a single Project on your University H: drive.

First, log on to a University PC (see Lesson 1.3) or UniDesk (see Lesson 1.4), and confirm that you can access your H: drive.

Creating a new Project

  1. Open RStudio.
  2. Select File > New Project...
  3. Select New Directory, followed by New Project.
  4. Enter hl10524_workbook as the directory name.
  5. Under Create project as subdirectory of, select Browse... and navigate to This PC > [your username] (H:).
  6. Select Create Project.

RStudio will create a new folder on your H: drive and open your Project.

5.4 Working directories

A working directory is the folder that R uses as its starting location when finding or saving files.

When you open an RStudio Project, its folder automatically becomes your working directory. This means you do not need to set it manually each time.

You can check your current working directory using the getwd() function.

Run in the Console

Run in the console
getwd()

You should see an output similar to:

Example output
[1] "H:/hl10524_workbook"

The exact path may differ depending on how your H: drive is configured. However, it should end with hl10524_workbook.

Changing your working directory

If you need to change your working directory manually, you can do this through RStudio:

  1. Select Session > Set Working Directory > Choose Directory...
  2. Navigate to the folder you want to use, such as This PC > [your username] (H:) > hl10524_workbook.
  3. Select the folder and confirm your choice.
  4. Run getwd() again to check that the working directory has changed.

However, when working within an RStudio Project, we recommend keeping the Project folder as your working directory. If the directory is incorrect, reopening your .Rproj file will usually restore it.

5.5 Creating R scripts

Now that you have created your RStudio Project, let's create your first R script within it.

So far, you have been running R code directly in the Console. However, code entered into the Console is not automatically saved in a script for future use.

An R script is a file (.R) that allows you to write, save, and run multiple lines of R code. This means you can return to your work, make changes, and run the same code again later.

Creating an R script

  1. Make sure your hl10524_workbook Project is open.
  2. In RStudio, select File > New File > R Script.
  3. A new blank script will open in the Source pane (top-left).
  4. Select File > Save As... and name your script lesson-3_script.R.
  5. Make sure the script is saved inside your H: drive > hl10524_workbook Project folder.

5.6 Running code from an R script

Unlike the Console, code written in a script does not run automatically.

You can run code in several ways:

  • One line: Place your cursor on the line and click Run (the small green arrow) at the top of the Source pane. Alternatively, press Ctrl + Enter (Windows) or Cmd + Enter (Mac).
  • Multiple lines: Highlight the lines you want to run, then click Run or use the same keyboard shortcut.
  • All lines above the cursor: Place your cursor on the line you want to run up to, then select Code > Run Region > Run from Beginning to Line. This runs all code from the start of your script through the current line.
  • Entire script: Click Source at the top of the Source pane. Alternatively, press Ctrl + Shift + Enter (Windows) or Cmd + Shift + Enter (Mac).

For now, we recommend running code line by line so you can see what each instruction does before running an entire script.

Your turn

In your new R script, enter the following code from Lesson 3:

Write in your script
library(beepr)beep()

Place your cursor on the first line and click Run. Then do the same for the second line.

You should hear a notification sound, just as you did in Lesson 3.

If you have not installed the beepr package on your current computer, you will need to install it first using install.packages("beepr") in the Console.

5.7 Annotating an R script

When writing R code, it is good practice to include notes explaining what different parts of your script do. These are called comments.

You can add comments using the # symbol. R ignores anything written after this symbol on the same line, allowing you to include explanations without affecting how your code runs.

Comments are useful for three purposes:

  • Script headers: A short description at the beginning of a script explaining its title and purpose.
  • Section headings: Dividing your script into clearly labelled sections.
  • Explanatory comments: Describing what particular lines of code do.

For example:

Write in your script
# HL10524 Workbook - Lesson 3# Purpose: Practising basic R functions and objects# 1. Loading packages ----# Load the beepr package so we can use its functionslibrary(beepr)# 2. Running functions ----# Play the default notification soundbeep()

In this example:

  • The script header identifies the script and briefly explains its purpose.
  • The section headings (# 1. Loading packages ---- and # 2. Running functions ----) divide the code into sections. RStudio recognises headings ending in ---- as code sections, making them easier to navigate.
  • The explanatory comments describe what the following lines of code do.
  • The code (library(beepr) and beep()) contains the instructions that R will execute.

Adding headings and comments makes your scripts easier to understand, particularly when returning to your work later.

5.9 Saving and reopening your work

Once you have finished working on your script, it is important to save your changes so that you can return to them later.

Step 1: Save your script

You can save your script in three ways:

  1. Select File > Save.
  2. Click the Save icon at the top of the Source pane.
  3. Press Ctrl + S (Windows) or Cmd + S (Mac).

Step 2: Reopen your Project and script

  1. Close RStudio.
  2. Open File Explorer and navigate to This PC > [your username] (H:) > hl10524_workbook.
  3. Double-click hl10524_workbook.Rproj to reopen your Project in RStudio.
  4. Open lesson-3_script.R from the Files pane.

Check that your code and comments have been saved correctly.

You should now have your first RStudio Project and an annotated R script that you can return to throughout the course.
